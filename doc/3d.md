# sextant for Python: 3D plots

A 3D scene is one more kind of cell in a figure's subplot grid. It holds bars, surfaces, triangle meshes,
point clouds and paths, plus 2D planes carrying any 2D plot, and it draws in the window, in PNG and in SVG.
This page assumes the [API guide](api.md); every keyword option is in [reference.md](reference.md#3d-options).

## An Axes3D in the grid

```python
import numpy as np
import sextant

fig = sextant.Figure(width=1100, height=520)
fig.add_subplot(1, 2, 1).line(t, y).set_title("2D")

ax3 = fig.add_subplot3d(1, 2, 2)
(ax3.bar3d("xy", wavelengths, offsets, counts)
    .set_title("3D")
    .set_xtitle("wavelength (nm)").set_ytitle("offset").set_ztitle("counts")
    .set_view(-55, 25))
fig.show()
```

`add_subplot3d()` takes the same arguments as `add_subplot()` (`(rows, cols, index)`, a span
`(rows, cols, (first, last))`, or the index alone once the grid is known) under the same grid rules. A cell
holding the other kind is a `ValueError`.

An `Axes3D` is a sibling of `Axes`, not a subclass. It has the decoration you would expect (`set_title`,
`set_xtitle`/`set_ytitle`/`set_ztitle`, `set_xlim`/`set_ylim`/`set_zlim`, `set_xticks`/`set_yticks`/
`set_zticks`, `grid`, `set_axes_style`, `legend`, `set_colorbar_style`, `cla`) and its own plot methods, and
its calls chain. `grid()` is **on** by default in 3D.

**Every axis is normalized onto a box.** A limit sets the range the box spans, not the box's size:
`set_xlim()` relabels that axis and remaps the data onto the same box, which lets three quantities in
different units share one scene. The proportions are set separately:

```python
ax3.set_box_aspect((2, 1, 0.5))     # x twice as long as y, z half
```

Limits are automatic until set, padded as in 2D.

## Grids and orientations

`bar3d` and `surface` take their data on a grid `u × v` and rise along the third axis. The orientation, a
string, names the two axes the grid spans:

| Orientation | Grid spans (u, v) | Bars and surfaces rise along |
|---|---|---|
| `"xy"` | x, y | z |
| `"yz"` | y, z | x |
| `"zx"` | z, x | y |

`heights` is a 2-D array of shape **`(len(u), len(v))`**: `heights[i, j]` belongs to `(u[i], v[j])`. That is
the shape `numpy.histogram2d(xs, ys)` returns, and the transpose of what `numpy.meshgrid(u, v)` produces
(use `meshgrid(u, v, indexing="ij")`, or pass `Z.T`):

```python
u = np.linspace(-2, 2, 40)
v = np.linspace(-1, 1, 30)
U, V = np.meshgrid(u, v, indexing="ij")      # shapes (40, 30)
ax3.surface("xy", u, v, np.exp(-(U**2 + V**2)))
```

A 2-D array of any other shape is a `ValueError` (a transposed grid has the right number of values and would
otherwise be drawn wrongly). A flat array of `len(u) * len(v)` values, u major, is accepted too.

## Camera

```python
ax3.set_view(-55, 25)                          # azimuth, elevation, in degrees

ax3.set_camera(azimuth=-58, elevation=24, zoom=1.2, projection="perspective", fov=30)

ax3.set_projection("perspective").set_fov(60)
```

Azimuth turns about the box's z axis (0 looks along +x); elevation is the angle above the xy plane, clamped to
±89°. There is no camera distance: the box's outline is fitted to the cell every frame, so the picture fills
its cell at any angle, and `zoom` scales that fit.

**Orthographic** (the default) keeps parallel edges parallel, so lengths compare anywhere in the box.
**Perspective** adds depth cues; `fov` (default 45°, 5–120°) sets how strong they are.

`ax3.camera()` returns the current camera as a dict, including a view the user dragged in the window:

```python
cam = ax3.camera()
# {'azimuth': -60.0, 'elevation': 30.0, 'target': (0.0, 0.0, 0.0), 'zoom': 1.0,
#  'projection': <Projection.ORTHOGRAPHIC: 'orthographic'>, 'fov': 45.0}
ax3.set_camera(**cam)                          # round-trips
```

`set_camera()` replaces the whole camera: fields you leave out return to their defaults. `target` is the
box-space point the camera orbits. `set_default_camera(...)` sets the camera a double-click in the window
returns to.

**In the window**, with Edit → Navigate on and the 3D subplot selected:

| Input | Effect |
|---|---|
| Left-drag | Orbit |
| Wheel | Zoom |
| W / S | Zoom in / out (orthographic), move toward / away (perspective) |
| A / D | Slide the view left / right |
| Q / E | Slide the view along the box's z axis |
| Double-click | Back to the default camera |

## bar3d

```python
ax3.bar3d(orient, u, v, heights, *, bottoms=None, **Bar3DOptions) -> Axes3D
```

```python
quarters = [1, 2, 3, 4]
regions = [1, 2, 3]
(ax3.bar3d("xy", quarters, regions, base, color="blue", width=0.6, depth=0.6, edges=True, name="product A")
    .bar3d("xy", quarters, regions, extra, bottoms=base, color="orange", width=0.6, depth=0.6, edges=True,
           name="product B")
    .legend())
```

A bar per grid point, `width` × `depth` of the grid spacing across (1.0 makes neighbours touch). Every bar
stands on `bottom` (default 0) unless you pass `bottoms`, one base per bar shaped like `heights`, which is how
bars stack. `shading` darkens each face by its angle to a light fixed in the box. `edges=True` outlines every
bar. `name` keys the grid in the legend.

## surface

```python
ax3.surface(orient, u, v, heights, **SurfaceOptions) -> Axes3D
```

```python
ax3.surface("xy", x, y, z, colormap=True, cmap="coolwarm", colorbar=True, name="z",
            edges=True, edge_alpha=0.35)
```

A sheet over a `u × v` grid of at least 2 × 2. It has one flat `color`, or with `colormap=True` it is
coloured by height through `cmap`. `vmin` and `vmax` default to the surface's own range (unlike 2D, where they
default to 0..1). `edges=True` draws the sampling grid as a wireframe. `name` titles the colorbar when
colour-mapped, and otherwise keys the legend.

## surface_tri

A sheet on a triangle mesh, for data that is not on a grid.

```python
ax3.surface_tri(x, y, z, triangles=None, *, orient=None, colors=None, **SurfaceTriOptions) -> Axes3D
```

```python
# Explicit topology: an (n, 3) integer array of vertex indices.
ax3.surface_tri(x, y, z, tri, color="cyan")
ax3.surface_tri(x, y, z, tri, colors=values, cmap="cividis", colorbar=True)

# Or let sextant triangulate scattered points projected onto a plane:
ax3.surface_tri(x, y, z, orient="xy", colors=z, colorbar=True)
```

Give **exactly one** of `triangles` and `orient` (both or neither is a `TypeError`).

- `triangles` holds three vertex indices per triangle, as matplotlib's `triangles` does: an `(n, 3)` array or
  a flat one, of any integer dtype. Floats are a `TypeError`; a negative index is a `ValueError`.
- `orient` triangulates the vertices once, when plotted, by a Delaunay triangulation of their projection onto
  that plane. The triangulation fills the convex hull, so for a concave domain (an L shape, a ring) pass
  `triangles` yourself. Collinear points are a `ValueError`.

`colors`, one value per vertex, colour-maps the mesh; the colour interpolates across each triangle. Shading is
per face, and both sides of a face are lit.

## scatter3d

```python
ax3.scatter3d(x, y, z, *, colors=None, err=None, **Scatter3DOptions) -> Axes3D
```

```python
ax3.scatter3d(x, y, z, color="orange", size=12, marker="triangle", name="beta")
ax3.scatter3d(x, y, z, colors=values, size=9, depthshade=0.45, colorbar=True, name="value")
```

Markers at points in space. **In 3D, `z` is a coordinate**; the colour value is `colors` (in 2D's
`scatter_z`, z is the colour). Markers keep their pixel size at any depth. `depthshade` darkens a marker with
its distance from the camera, 0 (the default) being off. `alpha` defaults to 1 here, unlike 2D's 0.8.

## line3d

```python
ax3.line3d(x, y, z, *, colors=None, err=None, **Line3DOptions) -> Axes3D
```

```python
ax3.line3d(x, y, z, color="gray", linewidth=2, loop=True, name="orbit")
ax3.line3d(x, y, z, colors=t, linewidth=3, cmap="turbo", name="colour-mapped")
```

A path through the points in order, flat or colour-mapped along its length. `linewidth` is in pixels at the
box centre, so under perspective a far stretch is thinner. There is no `linestyle`. `loop=True` closes the
path. At least two points.

## Plane2D: 2D plots in the scene

`plane(orient, offset=0.0, **Plane2DOptions)` places a 2D plot area in the scene, facing along one axis at an
offset (in data units along that axis), and returns it to draw on:

```python
# Floor: a heatmap with contours, at z = 0.
ax3.plane("xy", 0.0).heatmap(f, (0, 4), (0, 4), cmap="magma", colorbar=True,
                             contours=[0.25, 0.5, 0.75], contour_color="white")

# Back wall at y = 4: a line, in (z, x).
ax3.plane("zx", 4.0).line(zs, xs, name="profile")

# Side wall at x = 0: bars, in (y, z).
ax3.plane("yz", 0.0).bar(by, bh, name="totals")
```

A `Plane2D` has `line`, `scatter`, `scatter_z`, `bar`, `heatmap` and `imshow` with the same arguments as on
`Axes` (not `hist`: compute a histogram and use `bar3d`). Coordinates are the scene's own, along the two axes
the orientation names, in this order:

| Orientation | First coordinate | Second coordinate |
|---|---|---|
| `"xy"` | x | y |
| `"yz"` | y | z |
| `"zx"` | z | x |

A plane is **not** an `Axes`: limits, ticks, titles and the legend belong to the scene, and the plane's data
feeds the scene's automatic limits.

- `alpha` (keyword of `plane()`, or `set_alpha()` later) fades the whole plane.
- `visible=False` hides the plane without changing limits, colorbars or the legend, so toggling it never
  rescales the box.
- `set_offset(z)` moves it; `orientation()` and `offset()` read it back.
- A plane has the 2D read-back and update calls (`line_count()`, `line_data(i)`, `set_line_data(i, ...)`, …)
  and `cla()` for its own objects.

`ax3.plane_count()` counts the planes and `ax3.plane_at(i)` returns the i-th, the same object `plane()`
returned. A plane keeps its figure alive, like an axes.

## Error bars

`scatter3d` and `line3d` take `err=sextant.ErrorBar3D(...)`, with the rules of 2D's `ErrorBar`
([api.md](api.md#error-bars)) and a z axis: the fields are `x_`/`y_`/`z_` × `cap_`/`box_` × `lo`/`hi`.

```python
ax3.scatter3d(x, y, z, err=sextant.ErrorBar3D(z_cap_lo=spread, z_box_lo=sigma),
              color="red", size=10, errorbar={"linewidth": 1.5, "capsize": 8})
```

Cap data draws a whisker that turns to face the camera. Box data draws a translucent block per point,
`boxwidth` pixels wide along an axis without box data. The style (`errorbar=`) has `edge_alpha` beside
`box_alpha`. An unset colour is the series' colour, or black for a colour-mapped series.

## Translucency and depth order

Every 3D kind and every plane takes an `alpha`, and translucent geometry is drawn in the right order even
where objects pass through each other:

```python
(ax3.bar3d("xy", u, u, hb, alpha=0.55, edges=True, edge_alpha=0.6)
    .surface("xy", s, s, hs, colormap=True, cmap="plasma", alpha=0.6))
```

`edge_alpha` is separate from `alpha` on purpose: outlines faded along with their faces make a translucent
chart unreadable.

- **In the window and PNG**, translucency is resolved per pixel, through 8 layers by default. A scene stacking
  more translucent surfaces than that along one line of sight loses the farthest. Raise it for one file with
  `fig.savefig("scene.png", peel_layers=16)`.
- **In SVG**, it is resolved per polygon, splitting polygons where they intersect, within a work bound
  (`max_splits`, `max_tests`). When a bound is hit the file is still written, with part of it in plain depth
  order; the returned report says so and a `RuntimeWarning` is issued:

  ```python
  report = fig.savefig("scene.svg", max_splits=50_000)
  if not report.scene_order_exact:
      print(report.warning)
  ```

Opaque scenes (`alpha=1`, the default) never come near either bound.

## Box, axes, legend and colorbars

```python
ax3.set_box_style(panes=True, pane_color="#f4f4f8")
ax3.grid(True, color="#e2e2ea")
```

`set_box_style()` sets the back panes and how much of the cell is left around the box for labels (`margin`).
Axis annotation is `set_axes_style()`, shared with 2D. The axes follow the box's silhouette as it turns
(`"auto"`); `xaxis_y`, `xaxis_z`, `yaxis_x`, `yaxis_z`, `zaxis_x`, `zaxis_y` set to `"low"`, `"mid"` or
`"high"`, or an `origin_*` value, pin them to a face or a coordinate instead.

Tick labels are thinned where an edge is too foreshortened to hold them; `show_xticks`, `show_yticks` and
`show_zticks=False` hide an axis' ticks and labels. `legend()` keys every named series of
the scene, then of its planes in plane order. Colorbars are asked for by the plot objects (those on planes
included), and `set_colorbar_style()` styles all of the cell's bars.

## Text and annotations

Three calls, all drawn over the scene at a fixed pixel size whatever the camera does, and never hidden behind
geometry:

```python
(ax3.text("summit", x0, y0, z0, ha="center", va="bottom", dy=6)
    .annotate(x1, y1, z1, r"$z_{\min}$", 70, -40)     # text 70 px right, 40 down
    .text2d("run 41", 0.02, 0.95, va="top"))
```

- `text(s, x, y, z)` at a data point, projected; hidden while the point is outside the limits or behind the
  camera.
- `annotate(x, y, z, s, dx, dy, *, arrow=None)` puts the text `dx`, `dy` pixels (y up) from the projected
  point, with an arrow to it; hidden as `text()` is.
- `text2d(s, fx, fy)` at fractions of the frame from its bottom-left corner, fixed whatever the camera does: a
  caption.

They take the same keywords and `arrow` dict as 2D, math included (see the
[API guide](api.md#text-and-annotations)). Read back with `text_count()`, `text_data(i)` (a `Text3DData`) and
`set_text_data(i, ...)`; the short form `set_text_data(i, s, x, y, z=0)` keeps the rest, so a `text2d()` stays
in the frame and an `annotate()` keeps its offset.

## Live updates and reading back

Every 3D kind has `<kind>_count()`, `<kind>_data(i)` and `set_<kind>_data(i, ...)`, as in 2D:

| Kind | Read back as | Update with |
|---|---|---|
| `bar3d` | `Bar3DData(orient, u, v, heights, bottoms)` | `set_bar3d_data(i, orient, u, v, heights, bottoms=None)` |
| `surface` | `SurfaceData(orient, u, v, heights)` | `set_surface_data(i, orient, u, v, heights)` |
| `surface_tri` | `SurfaceTriData(x, y, z, tri, colors)` | `set_surface_tri_data(i, x, y, z, triangles, colors=None)` |
| `scatter3d` | `Scatter3DData(x, y, z, colors)` | `set_scatter3d_data(i, x, y, z, colors=None)` |
| `line3d` | `Line3DData(x, y, z, colors)` | `set_line3d_data(i, x, y, z, colors=None)` |

Each `set_` also takes the data object itself. `heights`/`bottoms` read back as `(len(u), len(v))`, `tri` as
`(n, 3)` `uint32`; `bottoms` and `colors` are `None` when not used.

```python
while not fig.wait_closed(1 / 30):
    z = step(z)
    ax3.set_surface_data(0, "xy", x, y, z)
    fig.refresh()
```

**Leaving out `colors` or `bottoms` removes them**: an update without `colors` makes a colour-mapped series or
mesh flat, and one without `bottoms` stands every bar on `bottom`. Pass them every time to keep them.
`set_surface_tri_data` takes the triangles as given and never re-triangulates (read them back from a
`surface_tri(..., orient=...)` mesh with `surface_tri_data(i).tri`).

A plane's objects are read and updated through the `Plane2D`, with the 2D names.

## Errors

`ValueError`, raised by the call, with nothing changed:

- a coordinate array that is empty or non-finite, or lengths that differ;
- `heights` (or `bottoms`) not of shape `(len(u), len(v))`, or flat with another length;
- a surface grid smaller than 2 × 2;
- a mesh with fewer than three vertices, a triangle index past the vertex count, or collinear points to
  triangulate;
- `colors` not one per point;
- a `line3d` with fewer than two points;
- a non-finite `vmin`/`vmax` or plane offset, or an empty or non-finite limit;
- an `ErrorBar3D` array that is not one per point;
- a non-finite text position, or a `Text3DData` with both `arrow` and `in_frame`.

`surface_tri()` with both or neither of `triangles` and `orient`, or with float triangles, is a `TypeError`.

## Known limitations

- **A perspective plane in SVG** is written as one polygon per heatmap cell, since SVG cannot express a
  perspective warp of an image. Above 20,000 cells it falls back to an affine image. PNG is unaffected.
- **A dashed line on a plane** is dashed in PNG and solid in SVG.
- **Very deep translucency** is peeled to 8 layers by default; running out of layers cannot report itself.
- **`hist()` on a plane** does not exist: use `bar3d` over a histogram you compute (`numpy.histogram2d`).
